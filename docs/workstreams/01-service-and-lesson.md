# 01. Service and lesson

## Why it matters
Teachers and students of live music need a lesson space where language is not a barrier and the human skill stays at the centre. Muse acts as a mediator, not a replacement for the teacher.

## Before the event
The concept, the teacher/student lesson flow and most of the Muse Lesson 2.0 interface design existed before 26 Oct 2026 (`docs/HACKATHON_CONTRIBUTIONS.md`). The idea of using Meta's open MMS-TTS voices for the lesson was first proposed by Muse Wonder on 19 Oct 2026, before the event; the integration described below is event work.

## Paths that did not work
- **First portal, 29-30 Oct.** Welcome, Leagues and three role cabinets written by Muse Wonder passed 24 of 24 frontend tests and deployed, and the project owner rejected them on structure and visual quality. Cause found in review: no designer had drawn these screens and the coding model invented the interface from a text brief. Lesson: tests and a successful deploy are not design acceptance. Design moved to Claude Design first, then code.
- **Three Muse Wonder visual directions, 30 Oct.** None was chosen; the first one was close to what Claude Design later drew.
- **Portal 2.0 by Muse Code, 3 Nov.** A 77-minute Muse Wonder Full run read the references and changed no files; an earlier Cabinet 1.3 run hung while starting an HTTP server. Portal 2.0 was ported by Claude (Anthropic) and is not credited to Muse.
- **A Muse Code run on 1 Nov** stopped after its maximum of 8 steps and was redone.
- **Lesson runtime v0.1, 31 Oct** (Kimi, third-party). Rejected by Codex (OpenAI) as a public backend: an unauthenticated demo route called Meta, lesson endpoints trusted a client-supplied actor, a fresh budget ledger replaced the real one, output limits of 300 tokens reproduced a real failure (298 of 300 tokens spent on reasoning, empty answer), and delivery continued when the validator failed. Replaced by the PR #3 base.
- **First real voice run, 3 Nov: PARTIAL.** VI→EN reached the listener by voice after review. EN recognition turned "A minor chord" into a distortion and added a contradictory "speed up", so the draft was rejected and not delivered. A control showed the source audio was recognised correctly and the copy sent over the real-time link lost "A".
- **Voice in the cloud, 3 Nov.** MMS was kept off: 1364 MiB of memory against a 512 MiB limit, and the licence question. Superseded on 4 Nov by an isolated 3072 MiB CPU worker; the licence question is still open. Fine-tuning a dedicated Muse voice was assessed (needs a clean single-speaker corpus per language) and not done. Device built-in voices were rejected by the project owner.
- **Third-party AI website builder and shared hosting, 28-29 Oct.** Abandoned: the builder's own agent wrote the first code, which could not be credited to Muse Wonder. Coding moved to Muse Wonder and hosting to a managed frontend host with a separate backend.
- **Signing the Convention by commenting "I sign" under a post, 29 Oct - 2 Nov.** Replies did not reach people and the profile link did not open; the owner replaced it with an explicit "Sign the Convention" button on the site. Names written in Devanagari or Tamil produced an empty notation signature in engine v3.
- **Muse Image backgrounds for Portal 2.0.** Specified, never run: no executor was assigned. Not claimed.
- **Watch app.** Planned on Galaxy Watch 6 Classic with timing tests for a tactile metronome; never built. The physical metronome moved to Sol Muse, the StackChan-based desk robot: its project software and the project's own prepared model are installed and loaded, its firmware build succeeded and it carries a moving-metronome module (see the table above). Physical acceptance of the tactile metronome mode is still open; the watch app stays Not done.

## Not claimed
- Student indicators, messages, video and lesson metrics in `web/` on `main` are simulated. That folder is not a live lesson service.
- Admission tests prove admission concurrency only, not media capacity. The health endpoint reports media_rooms=false and private_media_transport=false; the three-participant WebRTC test used generated media inside one test setup, without TURN or an SFU.
- No lesson with real participants through the service is documented, and no delivered lesson-hours are claimed. Lesson capacity is an operator setting, not a product-wide limit; the five-slot, twelve-contender setup is a test fixture only.
- Until 5 Nov 2026 the live site was served from draft branches that were not in `main`. Since pull request #10 (commit `fc6cc6c`) it is built from `main`, with evidence release `evidence-fc6cc6c434af`; that release dates the merge, not the individual earlier days.
- Sol Muse: installation of software and model is not acceptance of its physical modes; no new foundation model is claimed, and no model runs on the microcontroller.
- Mandatory scope set by the project owner, status on submission day (5 Nov 2026):
  - **Muse voice replies to both lesson participants: Prototype.** Technical integration only (tts=true, asr=true): no owner acceptance of voice quality, no human two-way EN/VI test on a physical Mac or phone, P95 latency target of 5 s not met (recognition 13-14 s, translation and review 24-31 s, cold speech start about 19 s; team QA log, 4 Nov), and the CC-BY-NC 4.0 licence is not cleared for the product.
  - **App on real watches (Galaxy Watch 6 Classic): Not done.** No watch app exists in any branch; the health endpoint reports watches=false and lists watches as not implemented.
  - **Physical tactile metronome: Prototype, acceptance open.** The watch path was not built. Sol Muse has project software installed, the project's own prepared model loaded, a successful firmware build and a moving-metronome module; physical acceptance of the tactile metronome mode has not been recorded.
