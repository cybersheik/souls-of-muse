### Контрольный замер: минимально простая задача для SAM

Кадр 480×270, один промпт «finger», пять повторов подряд: **0,7 / 1,4 / 1,9 / 2,0 / 2,2 с**. Сетевой круг до api.meta.ai из Сайгона без модели: 0,56–0,65 с на запрос. Значит нижняя граница облачного SAM на кадр — около 0,7 с, типично 1,5–2 с, и упрощать задачу дальше некуда: присвоение нот и поиск «палец над клавишей» делаются локально за микросекунды, во времени SAM их нет.

### «Плывёт»: разбор на цифрах

Айдар на слух: ансамбль не держит. Замер (`ensemble/measure_beats.py`, сухой прогон в реальном времени):
1. Первая причина — метр. Партитуру снял на сетке 3/8 Бетховена, а запись Айдара идёт в 4/4 при 148 bpm (отслежено по акцентам: контраст фаз 1,73 для такта в 4 доли). Сильные доли и смены аккордов ансамбля не совпадали с его тактами. Исправлено: `learn_score.py --beats` снимает партитуру по отслеженной сетке долей записи, `BAR` в партитуре, бас/щипки по метру.
2. Вторая — скачки позиции и темпа при каждой ноте. Исправлено: позиция и темп из регрессии по 12 последним сопоставлениям, шаг темпа ≤6 % за ноту, у планировщика собственные часы долей с фазовой подстройкой ≤25 % доли за долю. Ровность интервалов между сильными долями: MAD 32 → 14 мс (на старой сетке).
3. Остаток — рубато самого солиста. Такты записи длятся 1404–1823 мс при медиане 1608 (±13 %), такты ансамбля 1436–1842: он повторяет колебания записи с запозданием. Смещение сильной доли ансамбля относительно доли записи: медиана 51 мс, 90 % < 156 мс; на «второй попытке» 78/173 мс. Это и слышно как «плывёт»: ансамбль не угадывает замедления, которых ещё не было.

Что реально улучшит на слух: меньше щипков на слабых долях (они выдают рассинхрон сильнее всего), более ровный первый прогон солиста при записи партитуры, и живая проверка на пианино дочери, где исполнение ровнее GarageBand-наброска.

### 4б. Касание по тени (`keys/touch_shadow.py`) — код готов, ждёт съёмки с боковой лампой

Сверху силуэт висящего и касающегося пальца одинаков. При лампе низко сбоку у висящего пальца между его краем и тенью светлая щель (≈ высота над картоном / tg высоты лампы), у касающегося тень примыкает к кончику. Детектор: лучи от края кончика влево и вправо (ось пальца из суставов Vision DIP→TIP), яркость относительно уровня белой бумаги рядом, кожа отличается по насыщенности, чёрные клавиши и всё вне полоски исключаются через обратную гомографию чертежа; щель < 0,12 ширины пальца — касание, > 0,28 — висит.

Синтетика (картонка под перспективой, палец, тень со щелью 0…1,2 ширины пальца, размытие, шум, 150 случаев):

| Истина | Ответ детектора |
|---|---|
| касание, щель 0 (лампа слева/справа) | касание 20/24, остальное «не уверен» |
| висит, щель 0,4–1,2 ширины пальца, сбоку | висит 57/72, остальное «тени нет», ни одного «касание» |
| лампа за спиной или спереди | всегда «тени нет» — тень пальца тянется вдоль него сплошняком, щели нет даже у висящего |
| перепутано касание ↔ висит | 5 из 150 (3 %) |

Живые кадры вчерашнего звонка без бокового света: 44 кончика из 45 → «тени нет» (ложных касаний нет). Стоимость 6 мс на кадр на пять кончиков. В стенде `--press shadow`: касание два кадра подряд → нота; три кадра «не касается» → отпускание; где тени нет — прежнее правило удара. **Лампа строго сбоку от картонки** (слева или справа), не из-за спины играющего и не с дальнего края. Нужны фото Айдара: палец висит / касается, при такой лампе — для настройки порогов на настоящей коже и бумаге.

### 4в. Ансамбль: pymatchmaker против своего следящего (R-03) — остаёмся на своём

`ensemble/ab_matchmaker.py`: партитура `k_elise_aidar` → MIDI, события солиста → MIDI-файл, pymatchmaker 0.4 офлайн (методы pthmm, hmm, arzt, dixon, outerhmm; единицы проверены: доля = четверть = наша единица), наш Follower сухим прогоном. Истина: для записи Айдара — отслеженные доли, для синтетики — известная кривая темпа (разгон 0,40→0,33 с/долю, рубато ±10 %). Ошибка позиции в долях после каждой ноты; «потеряно» = ошибка > 1 доли.

| Вход | Свой следящий | pymatchmaker (лучший из пяти) |
|---|---|---|
| запись Айдара, 85 нот, без пропусков | медиана 0,07 · 90 % 0,19 · потеряно 0 % | 0,03 · 0,13 · 0 % (pthmm, outerhmm, arzt одинаково) |
| синтетика, пропуски 10 % | 0,08–0,09 · 0,19–0,20 · 0 % | 0,04–0,56 · 0,15–1,44 · потеряно 3–24 % |
| синтетика, пропуски 20 % | 0,06–0,09 · 0,16–0,17 · 0 % | 0,04–0,59 · 0,15–2,12 · потеряно 1–32 % |
| синтетика, пропуски 30 % | 0,08–0,11 · 0,16–0,18 · 0 % | 0,04–0,56 · 1,07–4,33 · потеряно 13–29 % |
| синтетика, пропуски 30 % + 5 % чужих нот | 0,07–0,09 · 0,16–0,22 · 2–5 % | 0,07–3,44 · 2,37–23 · потеряно 14–98 % |

На чистом входе pymatchmaker точнее вдвое (≈12 мс против 28 мс при 400 мс на долю), на входе со зрения (пропуски 20–30 %) он теряет позицию в каждом четвёртом-пятом случае, наш — нет. Оговорка: параметры pymatchmaker по умолчанию, под пропуски не настраивались; у него нет предсказания позиции между нотами, у нас есть темп и часы долей. Решение: блок слежения свой, pymatchmaker остаётся для сравнения.

### 4г. Ансамбль без метра (R-04) — сделано

`Follower(meter=False)`: доли не считаются; смена аккорда происходит на той ноте солиста, с которой по партитуре начинается новый аккорд; бас дублирует ноты солиста ниже G3 в его же момент, иначе звучит на смене аккорда; на смене аккорда мягкий щипок тоники. Сухой прогон на записи Айдара (`ensemble/measure_free.py`): 85/85 нот сопоставлено, 12 смен аккорда из 13 тактов (два F подряд слились), все 7 низких нот продублированы басом в тот же момент; отклонение смены аккорда от ближайшей сильной доли записи медиана 0 мс (по построению совпадает с нотой). Это снимает «чужой такт» на свободном наброске. Включение: `air_keys.py --ensemble kamila --ensemble-free`, `demo_audio.py … free`.
