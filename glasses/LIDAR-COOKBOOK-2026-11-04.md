# LiDAR iPhone 13 Pro — тракт глубины для стенда клавиатуры

Cookbook для DC1: как поставить на стенд «Souls of Muse» live-поток RGB+глубины с iPhone 13 Pro и чем глубина закрывает нерешённые проблемы летописи AI3-938–941. Написано по исследованию DZ1 от 04.11.2026; все допущения отмечены словом «проверить».

## 0. Вердикт — читать первым

**LiDAR не заменит Vision/SAM, он добавляет то, чего у RGB-методов нет вообще: третью координату.**

Что даёт глубина (256×192, ARKit sceneDepth):

1. **Маска «рука над плоскостью»** вычитанием плоскости стола/картонки. Не зависит от света и отражений — убивает проблему лака пианино (эксп. 15/25) и «окон, не размеченных вообще».
2. **z кончика пальца** → детект «нажата vs лежит» — главная нерешённая проблема летописи (детектор тени закрыт 02.11, DINO отличает «палец на клавише», а не «нажата»).
3. **Скорость снижения пальца** → упреждение нажатия для обычного темпа.

Чего LiDAR **не** даёт (и не должен):

- Точные x,y пальцев: на 40–60 см палец = 5–8 px глубины. x,y остаются за Apple Vision (5 мс, уже в стенде, эксп. 14), раскладка клавиш — за SAM 3.1 + чертёж картонки (`cardboard.py`, эксп. 16/24/26).
- Structure.io прямо предупреждает: руки/пальцы — не профиль LiDAR; класс виртуальных клавиатур на 3D-камерах (EPFL 2005, Sensors 2019) подтверждает метод (плоскость + порог глубины), но разрешение у нас грубее — отсюда осторожные пороги и временные фильтры ниже.

Границы применимости: дистанция rig 30–80 см (мин. диапазон LiDAR ~20–25 см, лучший SNR ~30 см, дальше палец < 4 px); картонка/бумага — отличная матовая цель; лак — проверить шагом 1; прямой солнечный ИК — избегать.

Приоритеты линии (допущение DZ1, менять по слову Айдара): 1) нажата-vs-лежит; 2) дрейф/две руки (их уже наполовину решает сам неподвижный rig — вывод эксп. 32); 3) отражения лака (бонус для настоящего пианино).

План по срокам (поправка 04.11: финал — **утро 05.11** по Алматы, не 09.11): окно на всю LiDAR-линию — одна ночь. Сегодня S0 (go/no-go, 2 минуты) и, если пройден, S1+покупка; интеграция в стенд — только если USB-стрим пойдёт сразу и без борьбы, иначе LiDAR на финал не едет (ролик уже снят, стенд живёт на Vision+SAM). Свой mini-app (план C) за ночь не успевает — снимается с финала, остаётся на будущее.

## 1. Шаг 0 — go/no-go за 2 минуты (до всякой установки)

Приложение **Night Vision Camera** (уже стоит на iPhone; это false-color глазок LiDAR-глубины):

1. Положить картонку на стол, держать iPhone на высоте будущей стойки 40–60 см, наклон 15–30° вперёд.
2. Открыть режим LiDAR/глубины, навести на пустую картонку, затем положить на неё руку с расставленными пальцами.
3. Критерии **GO**: (а) 4–5 пальцев различимы как отдельные возвышенности; (б) false-color пальца стабилен, не мерцает; (в) на глаз видна разница «палец висит ~1 см» vs «палец прижат».
4. Любой провал → попробовать 35–45 см; если и там пальцы слипаются в комок — **STOP**, LiDAR не для этого ракурса, копить глубину нечего.

Приложение **ScanToPrint** Айдара (проверено живьём 04.11, App Store id6776209746): LiDAR-сканер → меш → STL/OBJ для 3D-печати, оффлайн. Живая сетка на ~5 м — это ARKit **SceneReconstruction (mesh)**. Для нашей линии это: (а) хорошее известие — LiDAR живой и ARKit-тракт работает; (б) демонстрация разницы: **mesh ≠ depth**. Меш сглаженный, строится с запаздыванием и **тонкие объекты уровня пальца в него не попадают** — поэтому транспорт (Record3D / mini-app) стримит не меш, а покадровую карту глубины sceneDepth, где пальцы видны как отдельные возвышенности. Мини-тест в дополнение к Night Vision: поднести телефон к картонке на 40 см и посмотреть, ложится ли сетка на пальцы — ожидаемо нет или с большим лагом; это и объясняет, зачем нам depth, а не меш. Стрима/экспорта live у ScanToPrint нет, транспортом быть не может; опционально — статический STL стола с картонкой для декора/калибровки сцены.

### 3.1. Бесплатный путь: 3 записи вместо стрима (проверка физики до покупки)

Бесплатный тариф даёт 3 записи — это `.r3d`-файлы (RGB+глубина+позы, читаются тем же Python-пакетом). Живой стрим из них не получить, но они закрывают вопросы S0/S2 и калибровку порогов offline. Покупать Full Version только после того, как записи подтвердят, что пальцы различимы.

Сценарий трёх дублей (телефон закреплён: штатив/книги, 40–60 см над картонкой, наклон 15–30°; **между дублями 1 и 2 телефон не двигать** — плоскость должна совпасть):

| Дубль | Что в кадре | Длительность | Что даёт DC1 |

## 4. Модуль `depth_receiver.py` — скелеты (стык с текущим стендом)

Место: `~/Souls of Muse/glasses/keys/depth_receiver.py`. Всё — поверх существующего цикла `air_keys.py` + `cardboard.py`; ноты по-прежнему приходят из партитуры (`--press score`), глубина отвечает **только за момент касания** и за маску.

### 4.0. SAM и глубина: кто что ест (ответ на вопрос Айдара 04.11)

SAM (любая версия, включая наш локальный 3.1 на MLX) принимает **только RGB-кадры** — карта глубины в него не подаётся и не должна. Поток разбирается на две дорожки из одного синхронного кадра Record3D:

- **RGB → SAM (клавиши, периодически ~раз в 0,7–2 с, как сейчас; 0,09 с @336 px = потолок ~11 к/с — и не надо больше, раскладка статична) и → Apple Vision (пальцы x,y, каждый кадр, 5 мс);**
- **depth (256×192 float, метры) → чистая математика в numpy/opencv: плоскость, маска руки, z кончика. Нейросеть для глубины не нужна вообще.**

Сшивка дорожек — в нашем коде: клавиши из SAM и кончики из Vision проецируются в сетку глубины по интринсикам (либа отдаёт их на кадр). Бонус: маска глубины может служить ROI-приоритетом для SAM — сужает промпт и уменьшает ложные склейки клавиш (проблема «SAM слепил левый блок в одну», эксп. 16). Единственное, что проверить при S1 — фактическое разрешение/сжатие RGB-дорожки USB-стрима; для SAM @336–504 px это несущественно.


Обёртка над либой тракта: callback `(rgb, depth, conf, ts)` → в очередь кадров. Пара RGB/depth считается синхронной (у Record3D так и есть — проверить на дрейфе ts при S1). Для тракта C формат свой: JPEG + 16-бит PNG (сжатый zlib) глубины по WebSocket — парсер тот же.

### 4.2 Калибровка плоскости (один раз за сцену)
```python
# N=30 кадров пустой картонки -> поле D_plane(u,v)
# 1) медиана по времени для каждого пикселя области клавиатуры
# 2) RANSAC-плоскость по 3D-точкам (интринсики глубины из либы) -> вычесть вычисленную плоскость,
#    остаток (прогиб картонки) хранить как карту offset(u,v)
# Итог: D_plane(u,v) = a*u + b*v + c + offset(u,v)
```
Область клавиатуры брать из гомографии `cardboard.py` (чёрные клавиши уже сопоставляются — глубинную область резать по ней же).

### 4.3 Маска руки
```python
tau = 0.010  # м, старт; поднять до 0.012 при мерцании
hand = (depth < D_plane - tau) & (conf > conf_min)   # conf_min из карты confidence, старт 0.5
hand = cv2.morphologyEx(hand, cv2.MORPH_OPEN,  np.ones((3,3)))   # снять шум глубины
hand = cv2.morphologyEx(hand, cv2.MORPH_DILATE, np.ones((5,5)))  # добить края пальцев
```
Маска обновляется каждым кадром глубины; x,y кончиков из Vision проецировать в сетку глубины по интринсикам (RGB 1920×1440 → depth 256×192 — коэффициенты из либы, не вручную). Использование: фильтр кончиков Vision (кончик валиден, если его проекция попала в маску или ≤2 px от неё) и ROI-приоритет для SAM при переразметке клавиш.

### 4.4 Touch-детектор (главный блок)
На каждый кончик из Vision (трекинг по близости к прошлому кадру, как в стенде):

```python
# z_tip(t): медиана depth в окне 3x3 вокруг проекции кончика; буфер 5 кадров,
# временная медиана чтобы снять мерцание тонкого пальца
PRESS_Z   = 0.006    # м над плоскостью: ниже -> "касание"
HOVER_Z   = 0.012    # м: выше -> "отпустил"
DESCENT_V = -0.08    # м/с: скорость снижения для режима упреждения
DEBOUNCE  = 0.05     # с

press   = z_tip_med < D_plane_local + PRESS_Z and had_hover_within(z_tip_hist, 0.120) and not pressed
release = z_tip_med > D_plane_local + HOVER_Z for >= 2 frames
# режим темпа: vz < DESCENT_V -> prepare(press через ~vz/HOVER_Z), к финалу
```

Пороги — стартовые, обязательно калибровать на 30–секундном прогоне (см. S3). Палец «лежит» (постановка руки) отличаем от «нажал» именно парой «был спуск → касание → подъём»: лежащий без спуска не звонит.

### 4.5 Стык со стендом
- `air_keys.py`: событие note-on теперь приоритетно от depth (если тракт жив); DINO-кроп судья (`press_dino.py`) и правда из аудио (`note_onsets.py`) остаются вторыми голосами — консилиум 2 из 3 для медленных сцен, depth-соло для быстрых.
- Отражение лака: фильтр «кончик валиден только в маске глубины» снимает блики, которые Vision ловил на пианино.
- Огибающая скорости нажатия: velocity = f(min vz за спуск) → в `gm_synth.py` на MIDI velocity (к финалу, опционально).

### 4.6 Замер латентности end-to-end
Логировать: ts кадра глубины (из либы) / ts события press / ts note-on в синтезаторе. Цель **≤100 мс** тап→звук. Мерить честно отдельным прогоном: стук по клавише на камеру + осциллограмма аудио.

## 5. Rig и сцена

- Стойка: объектив в **40–60 см** над картонкой, чуть спереди, наклон 15–30° (пальцы не закрывают друг друга). Не ближе 30 см, не дальше 80 см.
- Подключение: USB к Mac (поток + заряд, WiFi не нужен для A/C-WiFi-вариантов — по факту тракта).
- Свет: любой для глубины; для RGB-Vision избегать контрового света (урок эксп. 15/17).
- Поверхности: картонка/бумага — отлично. Настоящее пианино: шаг 1 Night Vision прямо на лак — если глубина по лаку шумит, постелить матовый лист под руки (клавиши сами по себе — проверить).
- iPhone в Do Not Disturb + экран не гаснуть + зарядка (стрим ест батарею).

| лицензии | Arvos GPL-3 | ок для внутреннего стенда; код Arvos не тащить в репо продукта |
| время финала | S4 не успеваем | показывать S3-сцену (медленно по партитуре) — она уже снята в ролике, depth делает её надёжной |

## 9. Скелет тракта C — свой ARKit mini-app (к финалу)

Проект в Xcode: один ARSCNView/ARSession, конфиг `frameSemantics = [.sceneDepth]`, делегат `session(_:didUpdate frame:)`:

```swift
// на каждый ARFrame (до 60 fps):
// 1) depth = frame.sceneDepth!.depthMap        // CVPixelBuffer 256x192, Float32, метры
// 2) conf  = frame.sceneDepth!.confidenceMap   // ARConfidenceMap
// 3) rgb   = frame.capturedImage               // 1920x1440, YUV -> JPEG (compressionQuality 0.7)
// 4) отдача: WebSocket-фрейм { jpeg_b64, png16_depth_zlib_b64, ts_ns: mach_absolute_time }
//    (или бинарный: 1 байт тип + длина + тело; порт 8766, чтобы не пересекаться с /keys 8765)
```

Приём в Python: `websockets` + `cv2.imdecode`, дальше — те же 4.2–4.4 без изменений. Сборка на устройство с бесплатным Apple ID (7-дневный профайл — на финал пересобрать). Оценка DC1: ~150 строк Swift + 1–2 часа.
