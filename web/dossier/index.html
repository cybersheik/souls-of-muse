Development 01 · ServiceKEEPERS OF LIVE MUSIC
Cloud pilot

Souls of Muse & Muse Lesson

A service for human musical mentorship

Musicians need a shared place to meet, practise and pass on skills. Muse Lesson helps a human teacher guide another musician across a language barrier. The teacher leads; Muse supports the exchange.

What we built

The hackathon work brought the community portal, lesson interface and our own Harness together: participant login, roles, text sessions, English–Vietnamese interpretation, speech recognition, approval before delivery and spoken replies.

How it works

The Harness manages model roles, musical terminology, session state and delivery rules. Speech becomes a draft interpretation; a person can review and approve it before the other participant hears it. Muse is a model dependency inside this orchestration.

Models & toolsMeta speech recognition · Muse Spark · MMS-TTS for English and Vietnamese

Latest result · 5 November

The current portal and lesson code were merged and published on 5 November. A live check confirms that sessions, login, approval, speech recognition and TTS are enabled. The public service identifies itself as a pilot.

Evidence available

The public portal, code repository and capability endpoint are available. The portal includes the Convention, Leagues and lesson demonstration screens.

Current boundaryFull human acceptance of a bilingual lesson and the target response time remain open. Live media rooms, automatic matching and the watch application are not enabled in this cloud pilot.

Installed local application

MetaMezonin

A desktop environment built around Muse

A creative assistant needs tools, working memory and a place to keep its work. MetaMezonin provides that environment around Muse Wonder on the desktop.

What we built

The event work established an installed application with tools loaded on demand, persistent memory and retrieval, source-linked history, and a Muse Image route that can return generated imagery to Wonder for further work.

How it works

A custom runtime connects a conversation to tool discovery, execution and memory. Image generation is part of the same working context. Recovery scenarios and both source-level and packaged-application checks were recorded.

Models & toolsMuse Wonder via Meta Model API · Muse Image

Latest result · 5 November

The installed build and its recovery behavior are documented. A Muse assistant in MetaMezonin also contributed an earlier screenplay revision and substantive review to Ganesha.

Evidence available

Installed build, source checks, packaged checks and recovery records are retained with the project. The Ganesha case provides a concrete example of work produced through this environment.

Current boundaryThis is a separate desktop product from TopDog Colors. Proposed 3D avatars, movement analysis and home-practice extensions are future work. A public installer is not linked in this dossier.

Working local studio · active development

TopDog Colors

A media studio for musicians

Musicians need to turn a story and a collection of shots into a music video. TopDog Colors gives that work an editable visual workspace.

What we built

Building on the pre-existing studio, the hackathon work restored the Muse subscription route and developed a new editing interface: episode navigation, a player and timeline, three working slots, edit notes, change branches and a visual reference library.

How it works

The interface connects scenes, references and revisions. The current library was checked with 82 distinct images and six branches. Playback, timeline controls, closing behavior, navigation and a compact window layout were exercised.

Models & toolsMuse Wonder Full through the subscription workflow; current interface implementation used OpenAI Codex

Latest result · 5 November

The current interface passed 38 project checks and a TypeScript check. The filmed demonstration uses the real studio window. A separate restored-studio run records actual Wonder Full work.

Evidence available

Source, application builds, scene manifests and checks exist locally. The included live-action film shows the studio in use as the story returns to the day’s events.

Current boundaryAgent execution is disabled in the current interface-editing build. The spoken question in the live-action film is a staged macOS voice playback. The historical studio itself predates the event; restoration and the specific new work are the event contribution.

Development 04 · WearablesKEEPERS OF LIVE MUSIC
Local prototypes · demonstrated components

Three services for Ray-Ban Meta

Seeing, listening and supporting musicians

Glasses can bring assistance into the musician’s field of view and ear, while a connected computer or service performs the processing.

What we built

Three named services share a visual and voice-oriented interface: MuseEveryThings for musical surfaces and keys; Museon for a three-adviser contract review; MuseAudioNotes for an audio notebook. A separate depth receiver adds physical touch and hover sensing.

How it works

MuseEveryThings uses SAM 3.1 and DINOv2 in the vision work. Museon combines document reading with a council of Wonder and Spark advisers. MuseAudioNotes uses Spark to read chord material. The LiDAR branch receives depth from an iPhone over USB and calibrates the support plane.

Models & toolsSAM 3.1 · DINOv2 · Muse Wonder · Muse Spark

Latest result · 5 November

Museon was reported complete on its demo contract, finding all 18 planted issues. The other two services are in advanced prototype development. The overnight LiDAR run delivered 2,261 frames at 30 fps for more than 75 seconds with no disconnects.

Evidence available

Local service code, a clickable hub and recorded depth outputs exist. The live depth run produced press / hover / none states and automatic calibration. These are component results, separate from the narrative movie.

Current boundaryTouch accuracy against ground truth, frame-to-event latency and live key/MIDI correspondence still require the next measured run. The demo-contract score is not a general legal-accuracy score. SAM is not running inside the glasses.

Development 05 · RoboticsKEEPERS OF LIVE MUSIC
Software installed · model loaded

Sol Muse

A physical musical companion

Sol Muse brings the service into a physical object that can speak, move and participate in musical practice. Sol is the robot’s name; Muse is its family name.

What we built

The team prepared project software for a StackChan-based robot and a voice bridge. Music modules cover a moving metronome, a melody notebook that converts a hummed phrase into notes and MIDI, and a rap partner.

How it works

Device firmware connects to a service bridge and musical tools. The notebook pipeline extracts a note sequence and produces notation, editable MIDI and rendered audio. A four-note synthetic fixture is included as a small, inspectable example.

Models & toolsMuse Responses integration · project-specific model prepared and loaded

Latest result · 5 November

On 5 November the founder confirmed that the project’s own model had been prepared and loaded and its software installed. A successful firmware build and the musical tool modules are present. The notebook fixture produced C4–E4–G4–C5.

Evidence available

Firmware build records, module code and the synthetic notebook outputs are retained. The included MIDI, notation and audio demonstrate the fixture conversion without using a participant’s personal recording.

Current boundaryPhysical acceptance of each musical mode is tracked separately from installation. This result does not assert that a new foundation model was trained from scratch or that its weights run on the microcontroller. The watch application is a separate, unfinished item.

Development 06 · ResearchKEEPERS OF LIVE MUSIC
Completed campaign · public catalogue

Sound Made Visible

Bi-Level AutoResearch · Sci Sound Labs

A teacher can point to a change in sound when that change has a clear visual counterpart. This research explored mappings between musical quantities and visible form.

What we built

A bounded two-loop research pipeline, a fixed evaluator, renderers, experiment cards and films were developed. The inner loop proposed candidates; the outer loop redirected later work. Both research roles used Muse Wonder in separate contexts.

How it works

Twenty-four windows of 300 seconds produced 59 completed model requests: 48 inner and 11 outer. Eleven outer-loop changes were applied to later windows. The evaluator stayed frozen. The campaign explored ten families and produced nine calibrated families.

Models & toolsMuse Wonder for both research loops · Muse Wonder Full for the publication and polished media

Latest result · 5 November

The public Sci Sound Labs section now includes the development history, 24 experiment cards and 18 videos, including a separate 39-second performance loop. The campaign records 23 promising synthetic calibrations and one inconclusive result.

Evidence available

A public English article, experiment catalogue, films and jury report allow direct inspection of the method and numerical results. Early pilots and the stopped first run remain visible as development history.

Current boundary“Promising” means agreement with a frozen numerical/synthetic model. No physical validation or learning-benefit study was performed. The 24 windows are not 24 discoveries. Arbitrary live-audio recognition and an advantage over a fixed search strategy were not demonstrated.

Development 07 · CommunityKEEPERS OF LIVE MUSIC
Live entrance · developed identity system

A musical signature & a community

Convention · instrument Leagues · participation

Joining should express a shared commitment: keeping the ability to make music alive. The Convention gives that commitment a form, and a musical signature lets a person see and hear their name.

What we built

The project developed a name-to-melody engine, staff notation and playback, a Convention, the participant journey, a brand system, seven instrument Leagues and public social pages. The Cookbook connects these pieces into a coherent community design.

How it works

The signature engine maps normalized name characters to notes and renders the result as readable music. The participant journey moves from discovering the community to the Convention, a League, a personal space and an encounter with other musicians.

Models & toolsA deterministic music-signature engine; Muse supports the wider service experience

Latest result · 5 November

The current portal’s signing flow works, and the public Leagues and personal-space screens open. Facebook and Instagram pages exist. The current visual identity separates the community’s golden lyre from the Muse assistant character.

Evidence available

The public Convention and portal can be opened directly. The participant journey, visual system and community roles were developed in the launch Cookbook. Mentor, learner and volunteer express different ways to contribute.

Current boundaryThe complete account-linked membership lifecycle and every planned community space are not yet delivered. Multilingual signature edge cases remain. Soul ID, governance, automated social replies and live-stream programs have their own later implementation work.

Development 08 · CreativeKEEPERS OF LIVE MUSIC

Music and filmmaking with Muse

Ganesha · the live-action hackathon film

Creative production is a concrete test of collaboration: a story becomes shots, revisions, music and a finished film. The project produced two distinct films.

What we built

Ganesha developed through screenplay and storyboard work, character references, generated shots, editorial revisions and a composed score. The live-action film follows the loss and return of a piano, a cardboard keyboard, human mentorship and a musician’s return to making videos.

How it works

Wonder Full worked on the screenplay and storyboard; Wonder continued direction, review and composition. Muse Image supplied visual references. Krea generated video shots. Local editing and audio rendering assembled the film. Wonder wrote six melodic cells, harmony, percussion patterns and orchestration, preserved as score data and MIDI.

Models & toolsMuse Wonder Full · Muse Wonder · Muse Image; Krea for generated shots; human direction and local editing

Latest result · 5 November

Ganesha’s completed English-title master runs 82 seconds: 1,968 frames at 24 fps across 13 chapters. The new live-action jury edit runs 2:55.733 and adds the project identity, public pages and short technical explanations.

Evidence available

Both finished films are included in this package. Ganesha’s production records preserve completed model outputs, image receipts, score data, MIDI and checksummed masters. The short film is an artistic result with a documented production process.

Current boundaryThe live-action story contains staged interactions; it is not end-to-end acceptance evidence for every feature it portrays. Its added narrator uses macOS Daniel, and the studio’s question uses macOS Samantha. These voices are not presented as model-generated replies.

From the first sketch to this edition

The path matters.

The architecture journal, launch Cookbook and project dashboard provided the structure. Current product checks and delivery records supply the result.

Before the event

Define the human exchange

The early architecture journal put the Harness at the centre: shared rules, tools and knowledge around a model, with different device runtimes. The launch Cookbook added the participant journey, the Convention and a coherent visual identity. These are the design baseline.

26 Oct–5 Nov

Build the service and its tools

The event contribution includes the lesson pilot, speech and approval paths, portal integration, desktop orchestration, studio restoration and interface work. Existing foundations are identified separately from new implementation.

31 October

Complete a bounded research campaign

The corrected sound-to-form campaign ran 24 five-minute windows. A frozen evaluator, separate research roles, preserved failures and explicit limits turned a collection of visual ideas into an inspectable research result.

3–5 November

Connect interfaces to real inputs

The glasses work gained named service interfaces and a live depth input. Sol Muse received project software and a prepared model. Desktop creative tools supported actual screenplay, reference and review work.

5 November

Bring the latest results into the record

The current website code is published. Speech output is enabled. The live LiDAR run, installed robot software, current studio interface, Ganesha master and the 2:56 jury film are included in this snapshot.

What the early dashboard does not measureWorkflow states and weighted task percentages are not acceptance tests. This dossier uses concrete delivered outputs and measured runs, with public availability described separately.
